# 9. 클라우드별 설치 (업체 화면 따라 하기)

[English](#english) · 한국어

서버 회사마다 화면 이름과 위치가 달라요. 이 안내서는 업체별로 **어느 칸에 무엇을 붙여넣는지**, **방화벽과 고정 IP 를 어디서 여는지**를 정리했어요. 설치 내용은 항상 같아요. 설치 파일 만들기 페이지([00번 안내서](00-한번에-설치.md) ②)에서 만든 내용을 붙여넣으면 돼요.

> 화면 이름은 업체가 자주 바꿔요. 이름이 다르면 **비슷한 이름**을 찾으세요. 찾기 어려우면 업체 고객센터에 물어보세요. (Screen names change often. If a name differs, look for the closest one.)

## 먼저 준비할 것 (모든 업체 공통)

1. **운영체제: Ubuntu 24.04 LTS** 를 고르세요. (Ubuntu 24.04. Amazon Linux, Oracle Linux and CentOS are not supported.)
2. **형식 고르기:** 설치 파일 만들기 페이지에서 업체에 맞는 형식을 고르세요.
   - `#cloud-config` 칸: 사용자 데이터(User data), cloud-init 칸
   - `#!/bin/bash` 칸: 시작 스크립트(Launch script, Startup script, 초기화 스크립트)
   - 칸에 `#!/bin/bash` 로 시작하는 줄이 보이면 **시작 스크립트** 칸이에요. `#cloud-config` 로 시작하는 줄이 필요한 칸에서는 `#cloud-config` 형식을 쓰세요.
3. **방화벽:** 업체 방화벽(보안 그룹, 방화벽 규칙)에서 **22, 80, 443** 을 열어야 해요. 80 과 443 은 HTTPS 인증서 발급에 꼭 필요해요.
4. **고정 IP:** 가능하면 서버에 고정 IP 를 붙이세요. 서버를 다시 켤 때 IP 가 바뀌면 도메인 A 레코드도 바꿔야 해요.
5. 서버를 만든 뒤 **공인 IP** 를 메모하고, [00번 안내서](00-한번에-설치.md) ②의 DNS 화면에서 A 레코드 `@` 와 `www` 를 그 IP 로 설정하세요.

> 설치 파일 내용은 서버 만들기 화면에 한 번만 붙여넣으면 돼요. 나중에 칸을 고칠 수 없는 업체도 있어요 (DigitalOcean 등). 실수했다면 서버를 지우고 새로 만드세요.

| Google Compute Engine | 관리 › 시작 스크립트 (Startup script) | `#!/bin/bash` | 중간 |

## 업체별 순서

### AWS Lightsail · Launch script
1. Lightsail 에서 **인스턴스 만들기** → 서울 리전 → 플랫폼 **Linux/Unix**.
2. 블루프린트: **OS Only** › **Ubuntu 24.04**.
3. 아래 **시작 스크립트** 칸(Launch script)에 `#!/bin/bash` 형식 내용을 붙여넣으세요. (화면 이름이 다를 수 있어요.)
4. **고정 IP** 를 만들어 인스턴스에 붙이세요.
5. **네트워킹** 탭에서 **80, 443** 을 열어요 (22 는 기본으로 열려 있어요).
6. **인스턴스 생성**. 공인 IP 를 메모하세요.

### AWS EC2 · 사용자 데이터
1. EC2 › **인스턴스 시작** → 이름 → AMI **Ubuntu Server 24.04 LTS** (64-bit x86, 또는 arm64). 기본 Amazon Linux 는 안 돼요.
2. 인스턴스 유형, 키 페어를 고르세요. **t4g(Graviton)** 같은 arm64 유형을 고르면 AMI 도 arm64 를 골라야 해요.
3. **네트워크 설정 편집** › 보안 그룹에 **SSH 22, HTTP 80, HTTPS 443** 을 추가하세요.
4. **고급 세부 정보** 를 펼쳐 맨 아래 **사용자 데이터** 칸에 `#cloud-config` 형식 내용을 붙여넣으세요.
5. **인스턴스 시작**. 공인 IP 를 메모하세요. (고정 IP 는 **탄력적 IP** 를 붙이면 돼요.)

> 사용자 데이터는 16 KB 까지예요. 설치 파일은 이보다 훨씬 작아요. 콘솔에 붙여넣으면 자동으로 변환돼요.

### Google Compute Engine · 시작 스크립트
1. Compute Engine › **VM 인스턴스** › **인스턴스 만들기**.
2. 리전 **asia-northeast3 (서울)**. 부팅 디스크 **Ubuntu 24.04**.
3. **방화벽** 에서 **HTTP 트래픽 허용**, **HTTPS 트래픽 허용** 을 체크하세요.
4. **관리** › **자동화** 의 **시작 스크립트** 칸에 `#!/bin/bash` 형식 내용을 붙여넣으세요.
5. **만들기**. 외부 IP 를 메모하세요. 고정 IP 는 **IP 주소** 메뉴에서 바꿀 수 있어요.

> 시작 스크립트는 **서버를 켤 때마다** 실행돼요. 설치가 끝나면 이 칸을 비워 주세요. 그대로 두면 재부팅할 때마다 설치 프로그램이 업데이트를 다시 확인해요. (Google Compute Engine startup scripts run on every boot: clear the field once installed.)

### Microsoft Azure · 사용자 지정 데이터
1. 가상 머신 만들기 → 지역 **Korea Central (또는 Korea South)**.
2. 이미지 **Ubuntu Server 24.04 LTS**.
3. **인바운드 포트** 에서 **22, 80, 443** 을 선택하세요.
4. **고급** 탭 › **사용자 지정 데이터** 칸에 `#cloud-config` 형식 내용을 붙여넣으세요.
5. **검토 + 만들기**. 공인 IP 를 메모하세요. (화면 이름이 다를 수 있어요.)

> 브라우저 SSH 가 없을 수 있어요. 문제가 생기면 Azure 의 **직렬 콘솔**을 찾아보세요. (확인 필요)

### Oracle Cloud (OCI) · cloud-init 스크립트
1. 컴퓨트 › **인스턴스 생성**. 리전은 **대한민국 중부(춘천)** 또는 **서울** 을 고르세요. (화면에서 확인하세요.)
2. 이미지 **Canonical Ubuntu 24.04**. 모양(Shape)은 **x86** 을 권장해요. Arm 무료 사양은 한국 리전에서 쓸 수 없다는 보고가 있어요. (확인 필요)
3. **고급 옵션 표시** › **cloud-init 스크립트 붙여넣기** 칸에 `#cloud-config` 형식 내용을 붙여넣으세요.
4. **VCN 보안 목록**(또는 네트워크 보안 그룹)에 인그레스 규칙으로 **80, 443** 을 추가하세요. 22 는 보통 열려 있어요.
5. **생성**. 공인 IP 를 메모하세요.

### DigitalOcean · User data
1. Droplets › **만들기**. 리전은 목록에서 고르세요. (한국 리전은 없어요. 확인 필요)
2. 이미지 **Ubuntu 24.04 (LTS)**.
3. **고급 옵션** › **User data** 칸에 `#cloud-config` 형식 내용을 붙여넣으세요.
4. **방화벽**(선택)을 만든다면 **22, 80, 443** 을 열어요.
5. **만들기**. IP 를 메모하세요. 사용자 데이터는 만든 뒤에 바꿀 수 없어요.

### Vultr · User data
1. **Deploy Instance** › 위치 고르기 (서울이 보이면 골라요. 확인 필요).
2. **Ubuntu 24.04 x64**.
3. **Additional Features** › **User data** 칸에 `#cloud-config` 형식 내용을 붙여넣으세요.
4. 방화벽 그룹(선택)에 **22, 80, 443** 을 열어요.
5. **Deploy**. 콘솔은 **View Console** 로 열 수 있어요.

> 사용자 데이터는 처음 켤 때만 실행돼요.

### Hetzner · Cloud config
1. Cloud Console › 프로젝트 › **Create Server**.
2. Location 을 고르고, Image 는 **Ubuntu 24.04**.
3. Type 은 **CX 이상**을 고르세요. (확인 필요)
4. **Cloud config** 칸에 `#cloud-config` 로 시작하는 내용을 붙여넣으세요. 첫 줄이 `#cloud-config` 여야 해요.
5. **Firewall** 에서 **22, 80, 443** 을 열고 **Create**.

### Linode (Akamai) · Add User Data
1. **Create Linode** › **Ubuntu 24.04 LTS**.
2. Region 을 고르세요. (확인 필요)
3. **Add User Data** 칸에 `#cloud-config` 형식 내용을 붙여넣으세요. (화면 이름이 다를 수 있어요.)
4. **Firewall** 에서 **22, 80, 443** 을 열고 **Create**.

### 네이버 클라우드 · 초기화 스크립트
1. 콘솔 › **Compute** › **Server** › **서버 생성**.
2. 이미지 **Ubuntu 24.04**.
3. **ACG**(접근 제어 그룹)에서 **22, 80, 443** 을 허용하세요.
4. **초기화 스크립트** 를 선택하거나 새로 만들고 `#!/bin/bash` 형식 내용을 붙여넣으세요. (확인 필요)
5. **서버 생성**. 공개 IP 를 메모하세요.

### NHN Cloud · 사용자 스크립트
- 칸 이름과 형식을 아직 확인하지 못했어요. **화면 이름이 다를 수 있어요.** 찾기 어려우면 아래 "브라우저 SSH 한 줄" 방법을 쓰세요.

### 카카오 클라우드 · KT 클라우드 · 가비아 · 카페24
- 아직 이 업체의 사용자 데이터 칸을 확인하지 못했어요. 업체 고객센터에 **"서버를 만들 때 사용자 데이터(cloud-init) 또는 시작 스크립트를 넣는 칸이 있나요?"** 라고 물어보세요.
- 칸이 없으면 **브라우저 SSH 한 줄** 방법을 쓰세요.

## 칸이 없을 때: 브라우저 SSH 한 줄

서버를 만든 뒤 업체 화면의 **브라우저에서 SSH 연결**(또는 콘솔 접속)을 열고, 설치 파일 만들기 페이지에서 **"브라우저 SSH 한 줄"** 형식으로 만든 줄을 한 번 붙여넣으세요. 설치 코드와 도메인이 이미 들어 있어요.

```
curl -fsSL -o /tmp/dahae-install.sh <설치 파일 주소> && echo '<지문>  /tmp/dahae-install.sh' | sha256sum -c - && sudo env MALKKEUM_DOMAIN=<도메인> MALKKEUM_EMAIL=<이메일> MALKKEUM_SETUP_CODE=<설치 코드> MALKKEUM_FIREWALL=on bash /tmp/dahae-install.sh
```

> 이 방법은 서버가 켜진 뒤에 해요. 칸에 붙여넣는 방법보다 한 단계 많아요. 줄은 페이지에서 만든 것을 그대로 붙여넣으세요. 위 꺾쇠(<>) 자리는 사람이 채우는 자리가 아니라 페이지가 채운 값이에요.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 서버는 켜졌는데 `https://도메인/health` 가 안 열려요 | 10~30분 기다렸는지, A 레코드가 서버 IP 와 같은지 (https://dnschecker.org 에서 확인) |
| 80, 443 이 막혀 있어요 | 업체 방화벽(보안 그룹, 방화벽 규칙)에서 80, 443 을 열었는지 |
| "Amazon Linux" 나 다른 운영체제가 나왔어요 | 서버를 지우고 **Ubuntu 24.04** 로 새로 만드세요 |
| 설치 파일 칸이 없어요 | 위 "브라우저 SSH 한 줄" 방법을 쓰세요 |
| 설치가 실패했어요 | 설치 완료 알림 주소를 넣었다면 알림을 확인하고, 업체 콘솔에서 `sudo dahae logs` 화면을 개발자에게 전달하세요 |

## English summary

Each provider has its own screens. Pick **Ubuntu 24.04**, paste the setup text from the install page into the field the provider calls *user data*, *cloud-init*, *launch script*, *startup script* or *init script*, open ports **22, 80 and 443** in the provider firewall, then point the domain's **A records** (`@` and `www`) at the server's public IP. Check `https://<domain>/health`; `{"ok":true}` means the install finished. When no field exists, use the one-line browser SSH method above. Screen names are unverified for some providers, so confirm them on the live console before you rely on them.

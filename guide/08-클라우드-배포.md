# 8. 내 클라우드 계정에 다해 올리기

[English](#english) · 한국어

> AWS 를 쓰신다면 [10번 안내서](10-AWS-배포.md) 에 AWS 템플릿과 GitHub 자동 배포까지 정리해 두었어요.

이 안내서는 **사장님 명의의 클라우드 계정**에 다해 서버를 만들고, **사장님 도메인**을 연결해서, 운영을 시작하기까지의 전 과정을 한 곳에 모았어요. 서버를 빌리고 설치 명령을 붙여넣는 짧은 순서는 [0. 한 번에 설치하기](00-한번에-설치.md)에, 서버를 더 자세히 다루는 내용은 [1. 서버 설치 (자세히)](01-서버-설치.md)에 있어요. 여기서는 그 둘을 묶고, 클라우드 제공사 선택, 도메인 설정, 데이터베이스 백업을 외부 저장소에 두는 방법을 더 적었어요.

> 이 안내서에 나오는 명령과 화면 이름은 저장소의 설치 프로그램([deploy/install.sh](../../deploy/install.sh)), 서버 구성([deploy/docker-compose.yml](../../deploy/docker-compose.yml), [deploy/Caddyfile](../../deploy/Caddyfile)), 백업 코드([backup.rs](../../backend/crates/api/src/backup.rs))를 기준으로 썼어요. 가격과 제공사 화면 메뉴는 바뀌므로 적지 않았어요.

## 1. 시작 전에 준비할 것

| 준비물 | 왜 필요한가 | 언제 |
|---|---|---|
| 클라우드 계정 (결제 수단 등록 포함) | 서버를 빌리는 계정이에요. 사장님 이름으로 만드세요 | 서버 만들기 전 |
| 도메인 1개 (예: `myshop.co.kr`) | 고객과 직원이 들어가는 주소예요. 국내 도메인 등록 업체나 Cloudflare 에서 살 수 있어요 | 설치 전 |
| 인증서 안내를 받을 이메일 | 설치 질문 두 번째예요. HTTPS 인증서 관련 안내가 가요. 없으면 Enter 로 넘어가요 | 설치할 때 |
| 휴대폰과 인증 앱 (Google Authenticator 등) | 사장님 계정 로그인 때 6자리 코드를 써요 ([01번 안내서](01-서버-설치.md) ⑤) | 설치 직후 |
| 사업자 서류 | 결제, 문자, 사업장 정보를 연결할 때 필요해요. 설치 자체에는 없어도 돼요 ([02번 안내서](02-설정-마법사.md)) | 연결할 때 (나중에 가능) |
| 비밀번호 관리 앱 또는 USB | 서버의 보안 키 파일(`.env`)과 키 사본을 보관해요 (6번 참고) | 설치 직후 바로 |

## 2. 서버 고르기

### 운영체제와 구조

- **운영체제:** Ubuntu 24.04 LTS 를 권장해요. 업체별 화면 순서는 [9. 클라우드별 설치](09-클라우드별-설치.md)를 보세요. 설치 프로그램은 Ubuntu 22.04 와 Debian 12 도 지원해요 ([deploy/install.sh](../../deploy/install.sh) 2행, [DEPLOY.md](../DEPLOY.md) 서버 사양).
- **CPU 구조:** x86_64(amd64)와 arm64 를 지원해요. 다른 구조의 서버는 설치가 멈춰요 ([install.sh](../../deploy/install.sh) `arch_ok`).
- **지역:** **한국 서울** 리전을 권장해요. 고객과 직원이 한국에 있으면 응답이 빨라요. 고객 데이터도 사장님이 고른 국내 서버에 저장돼요.

### 사양 (설치 프로그램 검사 기준)

| 구분 | 메모리 | CPU | 디스크 | 설명 |
|---|---|---|---|---|
| 최소 | 1 GB 이상 | 1 vCPU | 여유 5 GB 이상 | 설치는 돼요. 메모리가 2 GB 보다 작고 스왑이 없으면 2 GB 스왑 파일을 자동으로 만들어요 (디스크 여유가 7 GB 이상일 때). 느릴 수 있어요 |
| 권장 최소 | 2 GB 이상 | 2 vCPU | 50 GB 권장 | 설치 프로그램이 안내하는 기준이에요 |
| 권장 (가이드 기준) | 4 GB | 2 vCPU | 50 GB | 손님을 받는 서버는 이 사양을 권장해요 ([00번 안내서](00-한번에-설치.md) ①) |

- 설치 프로그램은 메모리 약 900 MB 미만이면 설치를 멈춰요. 메모리가 부족하다는 메시지가 나오면 더 큰 사양을 고르세요.
- 디스크는 새 설치일 때 5 GB 이상 빈 공간이 있어야 해요. 다시 설치(업데이트)할 때는 2 GB 면 돼요.
- 컨테이너는 2 GB 서버 기준으로 메모리 상한을 나눠 두었어요: 데이터베이스 768 MB, API 512 MB, 웹 서버(Caddy) 256 MB ([docker-compose.yml](../../deploy/docker-compose.yml)).

### 서버 종류

| 서버 종류 | 지원 여부 | 메모 |
|---|---|---|
| 일반 가상 서버 (VM), Ubuntu 22.04 / 24.04 또는 Debian 12 | **지원해요** | 대부분의 클라우드 제공사에서 만들 수 있어요 (AWS Lightsail, AWS EC2, 네이버 클라우드 서버, Vultr, DigitalOcean 등) |
| arm64 가상 서버 | **지원해요** | 설치 프로그램이 arm64 를 받아요. 가격은 제공사마다 달라요 |
| 관리형 데이터베이스 (RDS, 네이버 클라우드 DB 등) | **지원하지 않아요** | 데이터베이스는 서버 안에서 PostgreSQL 컨테이너로 돌아가요. 별도의 관리형 DB 는 이 버전에서 연결할 수 없어요 ([docker-compose.yml](../../deploy/docker-compose.yml) `db`) |
| Ubuntu 20.04 이하, Windows 서버, 그 밖의 OS | **지원하지 않아요** | 설치 프로그램은 `apt-get` 을 쓰는 Ubuntu 또는 Debian 에서만 실행돼요 |
| 컨테이너 전용 서비스, 서버리스 | **해당하지 않아요** | 설치 프로그램이 서버에 직접 Docker, 방화벽(ufw), 예약 작업을 설치해요 |

### 2-1. 올라가는 구성 한눈에 보기

서버 1대에 모든 것이 들어가요. 데이터베이스를 따로 빌리지 않아요.

```
사장님 클라우드 서버 1대 (Ubuntu + Docker)
  web  (Caddy)          80, 443 포트만 밖에 열려요 → HTTPS 인증서, 도메인 주소
  api                   고객 앱과 콘솔이 쓰는 API. 밖에 열지 않아요
  db   (PostgreSQL 17)  서버 안에서만 접속해요. 데이터는 dbdata 볼륨
사진: uploads 볼륨 · 백업: /opt/malkkeum/backups/
밖에서: 도메인 A 기록 → 서버 IP,  외부 백업 → S3 호환 저장소 (권장)
```

- **데이터베이스:** 데이터베이스 주소나 계정을 넣는 칸이 없어요. 설치 프로그램이 `api` 가 서버 안 `db` 컨테이너에 붙도록 연결 주소를 만들어요 ([docker-compose.yml](../../deploy/docker-compose.yml)). 그래서 RDS 나 네이버 클라우드 DB 같은 별도 데이터베이스는 연결할 수 없어요.
- **도메인:** 루트 도메인(예: `myshop.co.kr`)은 설치 질문에 한 번 넣어요 (5-2). A 기록은 4번대로 넣어 두세요.
- **배포 순서:** 서버 만들기 (3번) → 고정 IP와 방화벽 → 도메인 A 기록 (4번) → 설치 명령 (5번) → 사장님 계정과 2단계 인증 (5-6) → 키 사본과 외부 백업 (6번) → 콘솔 연결 (7번).

## 3. 클라우드에 서버 만들기

아래 순서는 어느 제공사에서나 같아요. 메뉴 이름은 제공사마다 다르니, 화면에서 비슷한 이름을 찾으세요.

1. **서버(인스턴스) 만들기**를 눌러요.
2. 운영체제는 **Ubuntu 24.04 LTS**, 지역은 **서울**을 골라요.
3. 사양은 위 표의 권장 사양(2 vCPU, 4 GB, 50 GB)을 고르세요.
4. **SSH 키**를 등록해요. 비밀번호로만 접속하는 방식보다 키 로그인이 안전해요. 키를 만드는 방법은 제공사 안내를 따르고, 개인 키 파일은 사장님 컴퓨터에만 두세요.
5. 서버가 만들어지면 **고정 공인 IP** 를 연결해요. IP 가 바뀌면 도메인의 A 레코드를 다시 고쳐야 해요.
6. **방화벽(보안 그룹)** 에서 아래 포트만 열어요.

   | 포트 | 용도 | 열 범위 |
   |---|---|---|
   | 22 | SSH (서버 접속) | 가능하면 사장님 컴퓨터의 IP 만 |
   | 80 | HTTP (인증서 발급과 주소 이동) | 모든 곳 (인터넷) |
   | 443 | HTTPS (고객 앱, 콘솔, 웹사이트) | 모든 곳 (인터넷) |

   설치 프로그램도 `ufw` 방화벽을 켤 수 있고, 켜면 22, 80, 443 만 열어요 ([install.sh](../../deploy/install.sh) `firewall_setup`). 다만 Docker 가 연 포트는 `ufw` 를 거치지 않으니, **클라우드 방화벽 규칙도 함께** 두세요 ([DEPLOY.md](../DEPLOY.md) 1번 목록 2).
7. 서버의 **공인 IP** 를 메모해요. 예: `3.38.12.34`
8. 사장님 컴퓨터에서 접속을 확인해요: `ssh 계정이름@공인IP`. Ubuntu 이미지의 기본 계정 이름은 제공사가 알려 줘요 (보통 `ubuntu`).

### 제공사별 메모 (확실한 것만)

- **AWS Lightsail:** 고정 IP 는 **static IP** 로 만들어 인스턴스에 붙이세요. 방화벽 규칙에서 22, 80, 443 을 허용해요.
- **AWS EC2:** 고정 IP 는 **Elastic IP** 로 연결하고, **보안 그룹**의 인바운드 규칙에 22, 80, 443 을 넣어요.
- **네이버 클라우드 서버:** 공인 IP 를 연결하고, 서버의 **접근 제어(ACG)** 규칙에 22, 80, 443 을 넣어요.
- **Vultr, DigitalOcean:** 고정 IP 는 각각 **Reserved IP** 로 만들어 서버에 붙이세요. 방화벽은 제공사의 방화벽 메뉴에서 설정해요.

## 4. 도메인과 DNS 연결

### 4-1. A 레코드 두 개 넣기

도메인을 관리하는 화면(등록 업체 또는 Cloudflare)에서 아래 두 줄을 넣어요.

| 종류 | 이름 (호스트) | 값 (대상) | 설명 |
|---|---|---|---|
| A | 루트 도메인 (보통 `@` 또는 칸을 비워 둠) | 서버 공인 IP (예: `3.38.12.34`) | `myshop.co.kr` 주소 |
| A | `www` | 서버 공인 IP | `www.myshop.co.kr` 주소. 서버가 `https://myshop.co.kr` 로 자동 이동시켜요 |

- 이름 칸의 표기는 업체마다 달라요. 루트 도메인은 `@`, 빈칸, 또는 도메인 이름 그대로 넣기도 해요.
- `www` 레코드를 넣지 않아도 설치와 HTTPS 에는 영향이 없어요. 넣으면 `www` 주소도 같은 사이트로 이동해요 ([Caddyfile](../../deploy/Caddyfile) 175-178행).
- 주소는 `myshop.co.kr` 처럼 **루트 도메인**으로 쓰세요. 설치 질문에는 `https://` 나 경로를 붙여도 설치 프로그램이 떼어 줘요.

### 4-2. 기다리고 확인하기

- 저장한 뒤 반영까지 보통 몇 분이 걸려요. 길면 몇 시간이 걸릴 수 있어요.
- 사장님 컴퓨터에서 확인해요 (Windows, Mac 모두 가능):

  ```
  nslookup myshop.co.kr
  nslookup www.myshop.co.kr
  ```

  "주소" 항목에 **서버의 공인 IP** 가 나오면 연결된 거예요.
- 설치 프로그램도 같은 방식으로 확인해요. 아직 가리키지 않으면 `A 레코드 myshop.co.kr → 서버IP` 를 보여 주고, Enter 를 누르면 다시 확인해요 ([install.sh](../../deploy/install.sh) `dns_check`).
- **AAAA(IPv6) 기록**이 있으면 이 서버 주소여야 해요. 다른 주소라면 지우세요. 설치 프로그램은 이 기록도 확인해요 ([install.sh](../../deploy/install.sh) 297-303행).

### 4-3. Cloudflare 프록시(주황색 구름)는 끄세요

- Cloudflare 에서 A 레코드를 만들면 기본으로 **프록시(주황색 구름)** 가 켜져요. 이 상태에서는 도메인이 Cloudflare 의 IP 로 응답해서, 설치 프로그램의 "서버를 가리키는지" 확인이 실패해요.
- 설치 프로그램에는 프록시 설정 칸이 없어요. HTTPS 방식도 두 가지뿐이에요 (아래 표). 그래서 **DNS only(회색 구름)** 로 두세요.
- Caddy 가 인증서를 받으려면 인터넷에서 80, 443 포트로 이 서버에 직접 닿아야 해요.
- 백업용 Cloudflare R2 는 도메인과 별개라서 그대로 써도 돼요 (6번).

### 4-4. HTTPS 방식 (TLS_MODE)

| 설정 | 뜻 | 쓰는 곳 |
|---|---|---|
| 비워 둠 (기본) | 공인 인증서를 자동으로 받고 갱신해요 (Caddy) | **실제 운영** |
| `MALKKEUM_TLS=internal` | 설치 서버 안의 내부 인증 기관이 만든 인증서를 써요. 브라우저에서 경고가 나와요 | 설치 프로그램 테스트용만. 사장님 설치에는 쓰지 마세요 |

설치 프로그램은 이 두 가지 값만 받아요 ([install.sh](../../deploy/install.sh) 1369행, [Caddyfile](../../deploy/Caddyfile) 16-19행).

## 5. 설치 명령 실행하기

### 5-1. 명령 한 줄

> **개발자·설치 담당용이에요.** 사장님은 [00번 안내서](00-한번에-설치.md)의 **가장 쉬운 방법**(검은 화면 없음)으로 설치하세요.

서버 접속 화면(브라우저 SSH 버튼 또는 사장님 컴퓨터의 터미널)에서 아래 한 줄을 붙여넣고 Enter 를 누르세요.

```
curl -fsSL https://raw.githubusercontent.com/EricWijesinghe/Dahae-install/v1.6.0/install.sh | sudo bash
```

- `main` 은 안정(stable) 채널이에요. 베타 채널은 `beta/install.sh` 주소를 써요 ([install.sh](../../deploy/install.sh) 3~5행).
- 개발자가 특정 버전 주소를 따로 주면 그 주소를 쓰세요.

### 5-2. 설치 중 나오는 질문

| 질문 | 답 | 참고 |
|---|---|---|
| 서비스 주소(도메인) | `myshop.co.kr` | 형식이 틀리면 3번까지 다시 물어요 |
| 보안 인증서 안내를 받을 이메일 (없으면 Enter) | `owner@myshop.co.kr` | 비워도 돼요 |
| 방화벽(ufw)을 켜고 22·80·443 포트만 열까요? (y/N) | `y` 권장 | 기본은 `N` 이에요. 클라우드 방화벽을 이미 쓰고 있어도 한 겹 더 막아 줘요 |
| SSH 비밀번호 로그인을 끌까요? (y/N) | 키 로그인을 확인한 뒤 `y` | 이 질문은 계정에 SSH 키가 있을 때만 나와요. 키 없이 끄면 접속을 잃어요. 기본은 `N` 이에요 ([install.sh](../../deploy/install.sh) `ssh_keyonly_check`) |

- 도메인 연결이 아직이면 설치 프로그램이 안내를 보여 주고 Enter 를 기다려요. 건너뛰려면 `s` 를 입력하세요. 설치는 계속되고, 도메인이 연결되면 HTTPS 인증서가 자동으로 나와요.

### 5-3. 설치가 하는 일

- 서버 점검 (CPU 구조, 메모리, 디스크, 80·443 포트를 다른 프로그램이 쓰는지)
- 필요한 프로그램 설치, Docker 설치
- 보안 키 만들기 (`/opt/malkkeum/.env`)
- 데이터베이스, API, 웹 서버 시작
- 매일 새벽 3시 30분 백업
- 매주 월요일 새벽 4시 앱 자동 업데이트 (업데이트 전에 백업하고, 새 버전이 응답하지 않으면 이전 버전으로 되돌려요. 바꾸거나 끄는 법은 8-1)
- 자동 보안 업데이트, fail2ban(SSH 로그인 실패 차단)
- 관리 명령 `dahae` 설치

새 서버는 10~20분 걸릴 수 있어요.

**점검에서 막혔을 때:** "80/443 포트를 다른 프로그램이 쓰고 있어요" 라는 메시지가 나오면 그 프로그램을 끄고 다시 실행하세요. 메시지에 나온 예시는 `sudo systemctl disable --now nginx apache2` 예요. 다시 실행해도 안전해요.

### 5-4. 끝나면 나오는 화면

정상이면 이런 화면이 나와요.

```
✔ 설치가 끝났어요!   (채널: stable)

1) 브라우저에서 이 주소를 여세요:   https://myshop.co.kr/admin/
2) 설치 코드를 입력하고 사장님 계정을 만드세요:
       설치 코드:  (예: ABCD-EFGH-JKMN, 하이픈 포함 12자리)
3) [설정] 메뉴에서 결제·문자·로그인 연동을 차례로 연결하세요.

⚠ 비밀 키 사본을 꼭 만들어 서버 밖에 보관하세요:  sudo dahae keys-backup
```

- 도메인이 아직 연결되지 않았으면 "앱은 정상이에요. HTTPS 인증서는 아직이에요." 가 나와요. 몇 분 뒤 `sudo dahae status` 를 입력해 확인하세요.
- **설치 코드**는 처음 보인 뒤 **7일** 동안만 써요. 지났으면 설치를 도와준 개발자나 설치 담당에게 새 코드를 요청하세요 (개발자가 서버에서 `sudo dahae setup-code --renew` 를 실행해요. [install.sh](../../deploy/install.sh) `cmd_setup_code`).

### 5-5. 질문 없이 설치하기 (MALKKEUM_ANSWERS)

같은 설치를 여러 번 하거나 질문에 답하기 어려울 때는 답을 파일에 적어 둘 수 있어요.

1. 서버의 `/root/dahae-answers.txt` 같은 파일에 아래 두 줄을 적어요.

   ```
   DOMAIN=myshop.co.kr
   EMAIL=owner@myshop.co.kr
   ```

2. 설치 명령을 이렇게 바꿔 실행해요.

   ```
   curl -fsSL https://raw.githubusercontent.com/EricWijesinghe/Dahae-install/v1.6.0/install.sh | sudo env MALKKEUM_ANSWERS=/root/dahae-answers.txt bash
   ```

- 파일은 일반 파일이어야 해요 (바로가기 파일은 안 돼요). 값에는 공백, 역슬래시, `=` 를 쓸 수 없어요. `DOMAIN`과 `EMAIL` 두 줄만 읽어요 ([install.sh](../../deploy/install.sh) `load_answers`).
- `EMAIL=` 줄을 비워 두면 터미널이 있는 경우 이메일을 다시 물어봐요.
- 질문 없이 실행하면 방화벽은 기본으로 꺼져요. 켜려면 `MALKKEUM_FIREWALL=on` 을 같이 넣으세요 (`sudo env MALKKEUM_FIREWALL=on MALKKEUM_ANSWERS=... bash`). SSH 비밀번호 로그인은 질문 없이 끄지 않아요.
- 도메인이 아직 연결되지 않아도 기다리지 않고 설치를 끝내요.

### 5-6. 사장님 계정 만들기와 2단계 인증

1. 브라우저에서 `https://도메인/admin/` 을 열어요.
2. 화면에 설치 코드, 이름, 이메일, 비밀번호(12자 이상)를 입력해요.
3. 로그인하면 **2단계 인증 설정** 화면이 나와요. 인증 앱에 키를 추가하고, 앱에 보이는 6자리 숫자를 입력해요.
   2단계 인증이 끝나면 **복구 코드**가 나와요. 화면 안내대로 종이에 적어 안전한 곳에 보관하고 저장을 마쳐야 해요. 이 단계를 마쳐야 소유자 기능을 쓸 수 있어요.
4. 왼쪽 메뉴의 **[설정]** 으로 가서 7번 순서를 따라 해요.

설치를 끝내면 `sudo dahae status` 를 입력해서 "앱 정상"과 HTTPS 상태를 확인하세요. 명령은 모두 `sudo` 를 붙여 실행해요.

## 6. 데이터베이스와 백업

### 6-1. 데이터는 어디에 있나

| 무엇 | 어디 | 메모 |
|---|---|---|
| 데이터베이스 (PostgreSQL 17) | 서버 안 `db` 컨테이너, Docker 볼륨 `dbdata` | 인터넷에 열려 있지 않아요. 외부에 포트를 열 필요가 없어요 ([docker-compose.yml](../../deploy/docker-compose.yml) 19행, 36행) |
| 사진 등 업로드 파일 | Docker 볼륨 `uploads` | 백업 때 사진 파일도 함께 묶여요 |
| 백업 파일 | 서버 `/opt/malkkeum/backups/` | 서버 안에서 14일 동안 보관해요 |
| 보안 키와 설정 | 서버 `/opt/malkkeum/.env` | 여기 있는 `DATA_KEY` 가 백업을 풀 열쇠예요 |

### 6-2. 백업에는 무엇이 들어 있나

- **데이터베이스 백업** (`db-날짜.sql.gz.enc`): 매일 03:30 과 업데이트 직전에 만들어요 ([install.sh](../../deploy/install.sh) 예약 작업).
- **사진 파일 백업** (`uploads-날짜.tar.gz.enc`): 같은 시각에 함께 만들어요.
- 두 파일 모두 **AES-256-GCM 으로 암호화**돼요. 서버 디스크에도 평문 백업은 남지 않아요. 다만 암호화가 실패하면 평문을 지우지 않고 경고를 띄우며, 그때 업데이트·복원·되돌리기도 멈춰요 ([backup.rs](../../backend/crates/api/src/backup.rs) 1-8행, [DEPLOY.md](../DEPLOY.md) "Backups, RPO and RTO").
- **서버 안 백업**은 14일이 지나면 지워요 (`BACKUP_KEEP_DAYS=14`, [install.sh](../../deploy/install.sh) 425행).
- **외부 백업**은 콘솔에서 설정하면 보관 기간(기본 30일)에 따라 지워요.
- 최악의 경우 **하루치 데이터**를 잃을 수 있어요. 서버 디스크만 있으면 서버가 망가졌을 때 함께 사라져요. 그래서 외부 백업을 꼭 연결하세요.

### 6-3. 서버 안에서 바로 백업하기

```
sudo dahae backup
```

`backups/` 폴더에 새 `.enc` 파일이 생기고, 설정돼 있으면 외부 저장소에도 올려요. 외부 저장소가 실패해도 서버 안 백업은 남아요.

### 6-4. 외부 백업 연결하기 (콘솔의 "외부 백업 (S3 호환)" 카드)

S3 호환 저장소라면 어디든 쓸 수 있어요. 예: **Cloudflare R2**, **네이버 클라우드 Object Storage**, **AWS S3**.

1. 저장소 서비스에서 **비공개 버킷** 하나를 만들어요 (예: `dahae-backup`).
2. 접속 키를 만들어요.
   - R2: API 토큰을 만들고 권한을 **객체 읽기 및 쓰기** 로 정해요.
   - 네이버 클라우드: 마이페이지의 **인증키 관리**에서 액세스 키를 만들어요.
   - AWS S3: 버킷만 쓰는 전용 IAM 사용자 키를 만들어요.
3. 콘솔 왼쪽 메뉴 **[설정]** → **외부 백업 (S3 호환)** 카드를 펼쳐요.
4. 아래 칸을 채우고 **저장**해요.

| 화면의 칸 이름 | 저장 이름 | 예시 | 필수 | 조건 |
|---|---|---|---|---|
| 엔드포인트 | `endpoint` | R2: `https://<계정ID>.r2.cloudflarestorage.com` · 네이버: `https://kr.object.ncloudstorage.com` · AWS 서울: `https://s3.ap-northeast-2.amazonaws.com` | 예 | `https://` 로 시작하고, 공개 주소여야 해요 |
| 리전 | `region` | R2: `auto` · 네이버: `kr-standard` · AWS 서울: `ap-northeast-2` | 예 | 영문, 숫자, 하이픈만 |
| 버킷 이름 | `bucket` | `dahae-backup` | 예 | 소문자, 숫자, `-`, `.`, 3~63자 |
| Access Key | `access_key` | 키 ID | 예 | |
| Secret Key | `secret_key` | 시크릿 키 | 예 | 저장하면 암호화돼요. 한 번만 보이는 값이니 복사해 두세요 |
| 보관 기간(일) | `retention_days` | `30` | 아니요 | 기본 30, 1~3650 |

- 저장 이름은 [integrations.rs](../../backend/crates/api/src/integrations.rs) 의 백업 칸 정의와 같고, 칸 설명은 [setup_guides.dart](../../app/apps/console/lib/screens/setup_guides.dart) 에 있어요.
- AWS S3 는 이 코드의 연결 테스트 예시 주소로만 확인돼 있어요. 쓰기 전에 연결 테스트를 꼭 통과시키고, 막히면 개발자와 확인하세요.
- 저장해도 연결 확인은 자동으로 돌지 않아요. 저장하면 카드가 잠기니, **[잠금 해제 (소유자 코드)]** 를 눌러 사장님 2단계 인증 6자리 코드를 입력하고, **[연결 확인]** 을 눌러요. 작은 테스트 파일(`malkkeum/connection-test.txt`)을 올렸다가 바로 지워요. 초록색으로 "연결됨"이 나오면 성공이에요. 끝나면 **[잠그기]** 를 눌러요.
- 값이 틀리면 칸 옆에 이유가 나와요. 예: 엔드포인트 형식 오류, 버킷 이름 오류, 키가 맞지 않음.

### 6-5. 비밀 키 사본 (`keys-backup`) — 꼭 하세요

> **사장님은 개발자(설치 담당)에게 부탁하세요.** 키 사본은 아직 콘솔에서 만들거나 받을 수 없어요. (Until the console can do it, a developer makes this copy for you.)

외부 백업은 서버의 `DATA_KEY` 로 암호화돼요. 서버를 잃으면 `DATA_KEY` 도 함께 잃고, 외부 백업은 열 수 없어요. 그래서 키 사본을 서버 밖에 따로 보관해야 해요.

1. 개발자에게 **"보안 키 사본을 만들어 주세요"** 라고 부탁해요. 개발자가 서버에서 `sudo dahae keys-backup` 으로 만들고, 잠금 비밀번호(12자 이상)를 정해요.
2. 받은 파일(`keys-날짜.env.enc`)을 USB 나 비밀번호 관리 앱에 보관하세요. 카카오톡이나 이메일 본문에 붙여넣지 마세요.
3. 잠금 비밀번호는 서버 밖(비밀번호 관리 앱 등)에 따로 적어 두세요.
4. 보관을 확인하는 기록은 개발자가 남겨요.

- `.env` 파일의 키를 바꾸면(예: 키를 새로 만들었을 때) 키 사본을 다시 만들어 보관하세요 ([DEPLOY.md](../DEPLOY.md) 174행, `DATA_KEY` 와 `.env` 설명).
- 설치 직후에 `sudo cat /opt/malkkeum/.env` 로 내용을 복사해 두는 방법도 있어요 ([00번 안내서](00-한번에-설치.md) "보안 키 파일 보관").

### 6-6. 복원 연습 (정기 점검)

복원은 **지금 데이터를 백업 시점으로 되돌리는** 작업이에요. 운영 중인 서버에서 연습하면 실제 데이터가 바뀌어요. 그래서 점검은 두 단계로 나눠요.

**매달 점검 (운영 서버에서 해도 안전해요)**

1. 콘솔 [설정] 의 외부 백업 카드에서 **[연결 확인]** 을 눌러요. 카드가 잠겨 있으면 먼저 잠금을 풀어요 (7번).
2. `sudo dahae backup` 을 한 번 실행해요.
3. 외부 백업 목록에 방금 만든 파일이 보이는지 확인해요.

   ```
   sudo dahae restore-offsite
   ```

   이름 없이 실행하면 목록만 보여 줘요.

**실제 복원 연습 (별도 테스트 서버에서)**

- 테스트 서버에 같은 방법으로 설치하고, `keys-backup` 파일을 옮긴 뒤 아래 순서로 되돌려 보세요 (8번의 "서버 옮기기" 와 같아요).
- 운영 서버에서 직접 되돌리려면 아래 명령을 쓰세요. 실행하면 `yes` 를 입력하라고 물어요. 되돌리기 전에 현재 상태가 먼저 백업돼요 ([07번 안내서](07-운영-명령어.md) 4번).

  ```
  sudo dahae restore backups/db-20261110-033000.sql.gz.enc
  sudo dahae restore-offsite 이름
  ```

- 서버 안 파일 이름은 `db-날짜.sql.gz.enc` 형식이고, `restore` 는 `backups/` 폴더 안의 파일만 받아요.

### 6-7. WAL 보관 (개발자 설정)

WAL 보관(시점 복원, 약 5분 단위)은 개발자가 서버에서 따로 켜는 설정이에요. 사장님이 콘솔이나 명령으로 켜는 기능이 아니에요. 지금 상태에서 사장님이 믿을 복구 지점은 **하루 단위**예요 ([DEPLOY.md](../DEPLOY.md) "Backups, RPO and RTO", [RUNBOOK.md](../RUNBOOK.md) 복구 지점).

| 구글 로그인 | 구글 로그인 키 | [02번](02-설정-마법사.md) 5번 |

| 주소 검색 (도로명주소) | 주소 검색 키 | [02번](02-설정-마법사.md) |
| 외부 백업 (S3 호환) | 6번의 백업 저장소 | 6번 이 문서 |

- 카드에 값을 붙여넣고 **저장**해요. 저장된 값은 암호화돼요. 저장만으로는 연결 확인이 돌지 않아요.
- 저장하면 카드가 잠겨요. 바꾸려면 **[잠금 해제 (소유자 코드)]** 를 눌러요. 다 끝나면 **[잠그기]** 를 눌러요. 잠금을 푸는 것은 소유자만 할 수 있어요.
- 잠긴 카드에서는 연결 확인 버튼을 누를 수 없어요. 잠금을 푼 뒤 **[연결 확인]** 을 눌러요 (결제 카드는 **[API 키 확인]**). 초록색 **연결됨**이 나오면 성공이에요.
- 결제 (PortOne) 카드를 처음 저장할 때, 그리고 파트너 지급 카드를 토스 방식으로 저장하거나 토스 방식 설정을 지울 때는 사장님 2단계 인증 6자리 코드를 물어요.
- 결제 (PortOne) 카드에는 `<사장님 도메인 주소>/v1/webhooks/portone` 이, 파트너 지급 카드에는 `<사장님 도메인 주소>/v1/webhooks/toss` 가 보여요 ([setup.rs](../../backend/crates/api/src/routes/setup.rs) 587-588행). 각각 PortOne 콘솔과 토스 개발자 화면에 붙여넣어요. 파트너 지급 카드의 칸 이름에는 "PortOne 콘솔에 붙여넣기"라고 적혀 있지만, 그 주소는 토스용이에요. 확인 방법은 [결제 연동 설정](payments-setup.md) 3번에 있어요.
- 네이버 로그인 후 앱으로 돌아오는 앱 링크는 개발자와 함께 `dahae applinks` 로 설정해요 ([07번 안내서](07-운영-명령어.md) 9번).
- 외부 가동 확인(서버가 꺼지면 알려 줌)은 `sudo dahae heartbeat https://...` 로 설정해요 ([07번 안내서](07-운영-명령어.md) 8번).

## 8. 나중에 서버나 도메인을 바꾸기

### 8-1. 같은 도메인을 유지하며 업데이트하기 (지원)

사장님은 콘솔의 **서버 업데이트** 칸에서 업데이트해요. 개발자가 설치 명령을 같은 도메인으로 **다시 실행**하면 설정과 데이터를 그대로 두고 최신 버전으로 업데이트해요. 실행 전에 백업을 먼저 하고, 새 버전이 응답하지 않으면 이전 버전으로 되돌려요 ([install.sh](../../deploy/install.sh) 상단 설명). 자동 업데이트 요일과 시각은 개발자가 `sudo dahae update-schedule mon@04:00` 으로 바꿔요 (`off` 로 끌 수 있어요).

### 8-2. 새 서버로 옮기기 (지원)

서버를 바꾸는 방법은 개발자 문서에 정리된 절차예요 ([DEPLOY.md](../DEPLOY.md) "Backups, RPO and RTO", 예상 시간 약 1시간).

1. 새 서버를 3~5번 순서로 만들고, 5번 방법으로 설치해요. 도메인 연결은 4번 대로 기다리거나 나중에 해도 돼요.
2. **옛 서버**에서 `sudo dahae backup` 을 실행해 최신 백업을 만들어요. 그리고 `sudo dahae keys-backup` 으로 키 사본을 만들어요 (6-5).
3. 키 사본 파일을 **사장님 컴퓨터**로 받은 뒤 (6-5 방법), **새 서버**로 보내고 `/opt/malkkeum/backups/` 로 옮겨요.

   ```
   scp keys-날짜.env.enc 계정이름@새서버IP:~/
   sudo mv ~/keys-날짜.env.enc /opt/malkkeum/backups/
   ```

4. **새 서버**에서 키 사본을 넣어요 (파일 경로는 `/opt/malkkeum` 기준이에요).

   ```
   sudo dahae keys-restore backups/keys-날짜.env.enc
   ```

   잠금 비밀번호를 입력한 뒤, 확인 질문에 `yes` 를 입력해요.
5. 새 서버의 콘솔(`https://도메인/admin/`)에서 **외부 백업 (S3 호환)** 카드를 다시 입력하고 저장해요. 새 서버의 데이터베이스는 비어 있어서, 이 카드를 먼저 채워야 외부 백업 목록이 보여요.
6. 새 서버에서 목록을 보고 되돌려요.

   ```
   sudo dahae restore-offsite
   sudo dahae restore-offsite db-날짜.sql.gz.enc
   ```

   확인 질문에 `yes` 를 입력해요.

   복원 후에는 **예전 서버의 사장님 계정**(이메일, 비밀번호, 2단계 인증 앱)으로 로그인해요. 새 서버에서 새로 만든 계정은 복원하면서 사라져요.
7. 도메인의 A 레코드를 **새 서버 IP** 로 바꿔요. 몇 분 뒤 `sudo dahae status` 에서 HTTPS 를 확인해요.
8. 옛 서버는 새 서버가 정상임을 확인한 뒤에 끄세요. `sudo dahae uninstall` 은 서비스를 끄고 데이터는 남겨요. 확인 질문에 `yes` 를 입력해요.

> `sudo dahae uninstall --purge` 는 데이터와 백업까지 지워요. 도메인을 입력해야 실행되고, `--yes` 로는 넘어가지 않아요. 새 서버가 정상임을 확인하기 전에는 실행하지 마세요 ([install.sh](../../deploy/install.sh) `cmd_uninstall`).

### 8-3. 도메인 바꾸기 (콘솔)

사장님이 콘솔 **설정 > 도메인** 에서 바꿔요. 터미널은 필요 없어요 ([사장님 가이드](04-사장님-가이드.md#도메인-바꾸기)).

1. 새 도메인의 A 레코드(그리고 `www.새도메인`)를 이 서버 IP 로 넣어요 (4번). **예전 도메인의 A 레코드는 지우지 마세요.**
2. 콘솔에서 새 도메인을 입력하고 [DNS 확인] → [바꾸기] → 사장님 인증 코드 → 서버 승인 코드.
3. 30초쯤 멈췄다가 새 주소로 돌아와요. 새 주소가 5분 안에 응답하지 않으면 자동으로 되돌리고 이유를 보여 줘요.
4. 예전 도메인은 계속 응답해요. 설치된 앱은 예전 주소로 계속 작동하고, 웹사이트 페이지만 새 주소로 넘어가요.
5. 화면의 체크리스트대로 바깥 서비스(웹훅, PG 사이트 주소, 네이버 콜백 추가, 검색 등록, 스토어 주소, GitHub `store` 변수)를 고치고, 새 스토어 빌드를 올려요.
6. 새 앱이 스토어에 나오고 최소 앱 버전을 올린 뒤에만 예전 도메인을 은퇴시키세요.

> **이 기능 전에 설치한 서버는 설치 줄을 한 번 다시 실행해야 해요.** 서버 작업 실행기와 `dahae` 명령은 `dahae update` 로 바뀌지 않아요. 같은 도메인으로 설치 줄(5-1)을 다시 실행하면 데이터는 그대로 두고 새 실행기가 들어가요. 그 전에는 도메인 바꾸기가 "거부됨"으로 끝나요. 도메인을 옮긴 뒤에는 `MALKKEUM_DOMAIN` 을 빼고 실행하세요 (.env 의 도메인을 써요). 넣으면 그 도메인으로 다시 옮겨 가요.

## English

This is the short English version of the Korean guide above. The Korean text is the reference. Command names, field names and screen names are the same in both.

**What this guide covers:** deploying the Dahae platform on your own cloud account, with your own domain, and running it for your cleaning business.

### 1. Before you start

- A cloud account with a payment method on file, in your company's name.
- A domain, for example `myshop.co.kr`. Buy it from a domain registrar or Cloudflare.
- An email address for certificate notices (optional in the installer).
- A phone with an authenticator app (for the owner's two-step sign-in).
- Business documents for payments and SMS later (not needed for the install itself).
- A password manager or USB stick for the server's key file and the key backup.

### 2. Choosing a server

- **OS:** Ubuntu 24.04 LTS recommended. Ubuntu 22.04 and Debian 12 are also supported ([deploy/install.sh](../../deploy/install.sh) line 2).
- **CPU:** x86_64 (amd64) or arm64.
- **Region:** Seoul, Korea recommended.
- **Layout:** one server runs three containers: `web` (Caddy, ports 80 and 443 only), `api` (not open to the internet) and `db` (PostgreSQL 17, not open to the internet). Photos are in the `uploads` volume.
- **Your database:** there is no field for a database address or account. The installer connects `api` to the `db` container on the same server, so you do not set up a cloud database.
- **Size:** minimum 1 GB RAM (the installer stops below about 900 MB). The installer's message asks for 2 GB or more. The guide recommends 2 vCPU, 4 GB RAM, 50 GB disk. A fresh install needs at least 5 GB free disk.
- **Database:** PostgreSQL 17 runs inside the server (a container). A managed cloud database is not supported in this version.
- **Server types:** any Ubuntu or Debian virtual machine works (AWS Lightsail, AWS EC2, Naver Cloud Server, Vultr, DigitalOcean and similar). Not supported: managed databases, Windows, other operating systems, container-only or serverless services.

### 3. Creating the server

1. Create a server with Ubuntu 24.04 LTS in the Seoul region, with 2 vCPU, 4 GB RAM and 50 GB disk.
2. Add your SSH key. Use key login rather than a password.
3. Attach a static public IP (AWS Lightsail static IP, EC2 Elastic IP, Naver Cloud public IP, Vultr or DigitalOcean Reserved IP).
4. Open only ports **22** (SSH, ideally your own IP only), **80** and **443** in the cloud firewall or security group. Docker ports bypass `ufw`, so keep the cloud firewall rules.
5. Connect once to confirm: `ssh <account>@<public IP>`.

### 4. Domain and DNS

- Add two **A records** that point to the server IP: one for the root domain (`@`) and one for `www`.
- Caddy redirects `www.` to the root domain when the `www` record exists ([deploy/Caddyfile](../../deploy/Caddyfile) lines 175-178). Without it, nothing breaks.
- Check with `nslookup myshop.co.kr` and `nslookup www.myshop.co.kr`. The answer must be your server IP.
- If an AAAA (IPv6) record exists, it must also point to this server, or be deleted. The installer checks it too.
- **Turn off Cloudflare's proxy (grey cloud, DNS only).** The installer compares the A record with the server's public IP, and a proxied record fails that check. The installer has no proxy setting.
- HTTPS modes: leave `TLS_MODE` empty for automatic public certificates (the normal choice). `internal` is for installer tests only; the installer accepts no other value.

### 5. Running the installer

Run this on the server:

```
curl -fsSL https://raw.githubusercontent.com/EricWijesinghe/Dahae-install/v1.6.0/install.sh | sudo bash
```

It asks for:
- **Domain** (for example `myshop.co.kr`)
- **Email** for certificate notices (Enter to skip)
- **Firewall (ufw)** on, allowing only 22, 80 and 443 (default no)
- **SSH password login off** (asked only when your account has an SSH key; default no)

It then checks the server, installs Docker, creates the keys in `/opt/malkkeum/.env`, starts the services, and sets up the daily backup at 03:30, a weekly app update (Monday 04:00 by default; it backs up first and rolls back if the new version does not answer; change or turn it off with `sudo dahae update-schedule`), automatic security updates, fail2ban and the `dahae` command. A new server takes 10 to 20 minutes.

When it finishes it shows the console address `https://<domain>/admin/` and a 12-character **setup code**, shown with hyphens (for example `ABCD-EFGH-JKMN`). The code is valid for **7 days**. To get a new one, ask your developer or installer.

**Unattended install:** put `DOMAIN=` and `EMAIL=` lines in a file (for example `/root/dahae-answers.txt`), then run:

```
curl -fsSL https://raw.githubusercontent.com/EricWijesinghe/Dahae-install/v1.6.0/install.sh | sudo env MALKKEUM_ANSWERS=/root/dahae-answers.txt bash
```

Values cannot contain spaces, backslashes or `=`. Add `MALKKEUM_FIREWALL=on` to turn on the firewall without a question.

**First sign-in:** open `https://<domain>/admin/`, enter the setup code, your name, email and a password of 12 or more characters, then scan the two-step sign-in key into your authenticator app and enter the 6-digit code. Then save the recovery codes shown on screen; owner features need this step. Then open **[설정]** (Settings) and follow the cards.

### 6. Database and backups

- **Where:** PostgreSQL in the `db` container (volume `dbdata`), photos in the `uploads` volume, backups in `/opt/malkkeum/backups/`, keys in `/opt/malkkeum/.env`.
- **Memory limits:** database 768 MB, API 512 MB, web (Caddy) 256 MB.
- **Backups:** a database dump and a photo archive, every day at 03:30 and before every update. Both are encrypted with AES-256-GCM. Local copies are kept 14 days. The offsite copy keeps 30 days by default (1 to 3650 days).
- **Manual backup:** `sudo dahae backup`.
- **Offsite backup:** in the console's **외부 백업 (S3 호환)** card, enter these fields and save. Saving locks the card. Unlock it with the owner code, press **[연결 확인]** (Check connection), look for the green **연결됨** (Connected), then press **[잠그기]** (Lock).

| Field on screen | Stored as | Example |
|---|---|---|
| Endpoint | `endpoint` | `https://<account-id>.r2.cloudflarestorage.com` (R2), `https://kr.object.ncloudstorage.com` (Naver Cloud) |
| Region | `region` | `auto` (R2), `kr-standard` (Naver Cloud), `ap-northeast-2` (AWS Seoul) |
| Bucket name | `bucket` | `dahae-backup` |
| Access Key | `access_key` | your key ID |
| Secret Key | `secret_key` | your secret (encrypted when saved) |
| Keep for (days) | `retention_days` | `30` (optional) |

- **Keys backup (required):** the offsite copy is locked with `DATA_KEY`, which is in `.env`. Ask your developer or installer to make the key copy and keep the file off the server. Without it, a lost server means lost backups.
- **Monthly check:** test the connection in the console, run `sudo dahae backup`, then check the list with `sudo dahae restore-offsite`.
- **Restore and owner login:** after a restore onto a new server, sign in with the owner account from the old server (email, password, two-step sign-in app). An account made on the new server is replaced.
- **Real restore practice:** do it on a separate test server. `sudo dahae restore <file>` and `sudo dahae restore-offsite <name>` overwrite the live data after you type `yes`.
- **WAL archiving** (point-in-time recovery, about 5 minutes) is an engineer-only setup. Without it, the recovery point is up to 24 hours.

### 7. Connecting services

Open **[설정]** in the console. The "서비스 시작 준비" screen lists the cards: business details, PortOne payments, payouts, Solapi SMS and AlimTalk, Firebase push, Kakao, Naver, Google and Apple sign-in, address search, and the offsite backup. Save puts the values in the card and locks it. It does not run a connection check. To check, unlock the card with **[잠금 해제 (소유자 코드)]**, press **[연결 확인]** (on the PortOne card, **[API 키 확인]**), look for the green **연결됨**, then press **[잠그기]**. Saved keys are encrypted. The first save of the PortOne card, and a save or clear of the payout card in Toss mode, asks for the owner's 6-digit code. The PortOne card shows `<your address>/v1/webhooks/portone` and paste it into PortOne. The payout card shows `<your address>/v1/webhooks/toss` and paste it into the Toss developer console (its label says PortOne, but the address is for Toss). See [the payment setup guide](payments-setup.md) and [guide 02](02-설정-마법사.md).

### 8. Changing the server or domain later

- **Same domain, new version:** run the installer again with the same domain. It backs up first and rolls back if the new version does not answer.
- **New server (documented):** install on the new server, run `sudo dahae backup` and `sudo dahae keys-backup` on the old one, copy the key file to the new server's `backups/` folder (copy it to your computer first, as in 6-5, then `scp` it to the new server's home folder and `sudo mv` it into `/opt/malkkeum/backups/`), run `sudo dahae keys-restore backups/<key file>` and type `yes` at the confirmation, enter the offsite card in the new console, run `sudo dahae restore-offsite <name>` with `yes`, sign in with the old owner account, move the A records to the new IP, then `sudo dahae uninstall` on the old server and type `yes` (not `--purge` until the new one is verified).
- **New domain (no documented procedure):** talk to your developer first. Apps need a rebuild because the API address is built in. Payment webhooks and social sign-in addresses must be updated.

### 9. Checklist

Account, domain and authenticator ready; Ubuntu 24.04 server in Seoul with a static IP; ports 22, 80, 443 open in the cloud firewall; SSH key login works; A records for root and `www` with the proxy off; `nslookup` matches; installer finished; setup code used within 7 days; owner account and two-step sign-in done; `sudo dahae status` healthy; keys backup made, stored off the server and confirmed; offsite card connected and tested; a backup appears in `restore-offsite`; payments, SMS and sign-in connected; heartbeat set up.

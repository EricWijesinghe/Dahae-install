# 3. 앱 출시 (App Store · Google Play)

앱은 **개발자가 GitHub Actions 로 빌드해서 DODA 의 스토어 계정에 올려요** ([guide 11](11-앱-직접-빌드.md)). DODA 는 스토어 계정을 만들고 개발자에게 관리자 권한을 줘요. DODA 가 할 기술 작업은 없어요. 맥(Mac)도, 코드도, 빌드 프로그램도 필요 없어요.

계정은 반드시 **사업자 명의**로 만들어요 (스토어 정책 — 앱 주인이 사장님이 되도록). 개발자는 사업자 계정을 소유할 수 없어서 (D-2 비자) DODA 가 계정 소유자예요.

## 준비물
| 계정 | 비용 | 소요 | 비고 |
|---|---|---|---|
| Apple Developer Program (**조직**) | 스토어 요금표 | 스토어 기준 | D-U-N-S 번호 필요 (무료 발급, 며칠 걸림) |
| Google Play Console (**조직**) | 스토어 요금표 | 스토어 기준 | 개인 계정은 출시 전 테스터 12명·14일 테스트가 의무라 조직 계정 권장 |

## A. Apple (한 번만)
1. DODA 가 developer.apple.com 에서 **조직**으로 가입 → 결제 → 승인 메일 기다리기. 승인 뒤 DODA 계정 소유자가 App Store Connect → 사용자 및 액세스 → 통합 → App Store Connect API → **액세스 요청** 을 한 번 눌러요 (계정 소유자만 할 수 있어요. 이게 없으면 개발자가 API 키를 만들 수 없어요)
2. DODA 가 개발자의 Apple ID 를 **Admin** 멤버로 초대해요. 개발자가 App ID 두 개, 앱 두 개, APNs 키를 만들어요 ([guide 11](11-앱-직접-빌드.md) 6번)
3. App Store Connect → 통합 → App Store Connect API 에서 키를 만들어요 (역할 **Admin**. App Manager 키는 자동 서명 내보내기에서 "Cloud signing permission error" 로 실패해요)
   - 내려받은 `.p8` 파일, **Issuer ID**, **Key ID** 는 개발자가 GitHub 환경 `store` 의 시크릿에 넣어요 (`ASC_KEY_P8_B64`, `ASC_ISSUER_ID`, `ASC_KEY_ID`). 저장소나 메일에 올리지 않아요 (아래 "키 보관")

## B. Google (한 번만)
1. DODA 가 play.google.com/console 에서 **조직** 계정으로 가입 → 등록비 결제 → 신원 확인
2. DODA 가 개발자의 Google 계정을 **관리자**로 초대해요. 개발자가 Play 서비스 계정을 만들어 **출시 관리자 (Release manager)** 권한을 주고 키를 `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` 에 넣어요 ([guide 11](11-앱-직접-빌드.md) 5번)
3. 앱 두 개 (다해 / 다해 파트너)는 개발자가 Play Console 에서 만들어요 (guide 11 5번 1항)

## 키 보관
`.p8` 파일, keystore 와 서비스 계정 키는 비밀번호와 같아요. 저장소, 카카오톡 단체방, 이메일 본문에 올리지 마세요. GitHub 환경 `store` 의 시크릿에만 넣고, 파일 사본은 비밀번호 관리 앱에 보관하세요 (guide 11 §3, §4).

## B-2. 간편 로그인 · 알림 (선택)
카카오·네이버·구글 로그인과 앱 알림을 쓰려면, 각 개발자 사이트에 **사업자 명의**로 앱을 DODA 가 등록하고 (개발자가 접근 권한으로 같이 해요), 키는 개발자가 `store` 환경에 넣어요 ([guide 11](11-앱-직접-빌드.md) 3·7번).

## C. 역할 나누기 ([guide 11](11-앱-직접-빌드.md) 1번)
- **DODA**: 스토어 계정 개설, 조직 가입, 관리자 초대, 계정 비용, 서버 콘솔 설정 마법사에 결제·문자 키 입력. 사장님이 [직원]에서 개발자에게 관리자 계정을 만들어 주면 문자·푸시·로그인 카드는 개발자가 처음 저장할 수 있어요. PortOne·토스 카드, 잠금 해제, 저장 뒤 연결 확인은 사장님 계정만 돼요
- **개발자**: 저장소 `store` 환경 설정, App ID·앱 생성, API 키 만들기, `store-apps` 워크플로 실행, 빌드, 업로드, 심사 제출
- 아이폰: **TestFlight** 로 올라간 빌드를 아이폰에서 "TestFlight" 앱으로 설치해 확인 (DODA 직원 또는 개발자)
- 안드로이드: Play **내부 테스트** 트랙의 초안을 확인해 휴대폰에서 설치해 확인 후 출시
- 심사 제출: 개발자가 Admin 권한으로 해요. DODA 가 원하면 DODA 직원도 같은 권한으로 제출할 수 있어요

## D. 심사 때 사장님/설치 담당이 할 일
- **심사용 계정**: 심사원은 한국 문자를 받을 수 없어요. 콘솔 [설정] → [스토어 심사용 데모 계정]에서 번호와 6자리 코드를 정해 켜고, 그 번호와 코드를 심사 메모에 직접 적어요. 14일 뒤 자동으로 꺼져요.
- 개인정보처리방침 주소: `https://도메인/privacy.html`, 계정 삭제 안내: `https://도메인/delete-account.html` (서버 설치 후 자동으로 생겨요)
- 스토어 설명 문구·데이터 보안 답변은 이 안내서 묶음의 `store/` 폴더에 있어요

심사 기간은 스토어 정책에 따라요. 승인되면 콘솔 [설정 → 사업장 정보 → 앱 스토어 주소]에 스토어 주소를 넣어 웹사이트 버튼을 켜세요.

## E. 스토어 사진 · 설명 문구
- 스토어 화면 사진은 개발자가 `docs/store/screenshots/` 에 만들어요 (고객·파트너 앱, 아이폰·아이패드·안드로이드 크기, 한국어·영어). 저장소에는 올리지 않고, 릴리스에 `dahae-store-images-<버전>.zip` 으로 첨부해요.
- 화면이 바뀌면 개발자가 다시 만들어요: `scripts/store/generate.sh`
- 설명 문구는 `docs/store/listing-*.md` 에 있고, 글자 수 제한은 `docs/store/check_listings.py` 로 확인해요.
- 개인정보 답변: Google 은 `docs/store/data-safety.md`, Apple 은 `docs/store/app-privacy.md`.
- 그 밖의 스토어 질문(광고, 대상 연령, 연령 등급, 금융 기능, 권한) 답변: Google 은 `docs/store/play-declarations.md`, Apple 은 `docs/store/app-privacy.md` 2·3항, 심사 메모는 `docs/store/review-notes.md`.

## 앱 업데이트
개발자가 새 태그 (예: `v1.6.1`) 를 만들고 `store-apps` 를 다시 실행해요 ([guide 11](11-앱-직접-빌드.md) 10번). 스토어 심사와 출시가 끝나면 휴대폰이 자동으로 업데이트해요.
